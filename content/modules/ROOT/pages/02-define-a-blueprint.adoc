== Create a Blueprint

Red Hat Lightspeed Image Builder Blueprints allow you to create, save, and edit revisions over time. A blueprint provides a declarative definition of how to assemble RHEL, including software package content and configuration options. We'll be using a blueprint to create a custom image for our lab.

From the Image Builder page, start a new image build to open the `Build an image` wizard. The wizard walks you through four steps — `Base settings`, `Repositories and packages`, `Advanced settings`, and `Review`.

== Base settings

=== Details and image output

Give your image a `Name`; a description is optional. Make it something unique, such as `rhelworkshop-<your initials>`.

Under `Image output`, choose the `Image type`. Image Builder gives you the option to build either a `Package mode` (traditional) RHEL installation, or an `Image mode` (bootc) based image. We will be using the traditional `Package mode`.

.Base settings — name and image type
image::2026/ib-wiz-step1-name.png[Base settings name and image type]

Next, select `Red Hat Enterprise Linux (RHEL) 10` for the release, and `x86_64` for your architecture.

Note that the `Target environment` can be set to a public or private cloud, or to other formats such as a raw `.qcow2` or an installer ISO for universal installation media. Let's choose `Virtualization - Guest image (.qcow2)`.

=== Register

We can also choose to automatically register our system. Let's set the `Registration method` to `Automatically register to Red Hat Hybrid Cloud Console`, and leave the options for `Enable predictive analytics and management capabilities` and `Enable remote remediations` enabled. This allows you to more proactively manage your RHEL system from the Hybrid Cloud Console.

An activation key tells the image which account to link this system to when it automatically registers. Normally you would create a key that fits the purpose of this system and select it here. Because this is only a demo, it does not matter which activation key you choose — leave it at whatever default was selected for you.

.Register — registration method and activation key
image::2026/ib-wiz-step1-reg.png[Register]

=== Security and compliance

Scroll down in this window and you will see options for a repeatable build, and a security and compliance policy. Compliance policies let you apply a standard OpenSCAP profile, or select a custom policy that you have tailored for your organization using the Red Hat Lightspeed compliance tool.

Let's select `Use a default OpenSCAP profile`, and choose `CIS Red Hat Enterprise Linux 10 Benchmark for Level 2 - Server` in the drop-down list.

.Security — default OpenSCAP profile
image::2026/ib-wiz-scap.png[Security OpenSCAP profile]

Now press `Next`.

== Repositories and packages

On the `Repositories and packages` page, you can add custom software repositories that you have defined within the Hybrid Cloud Console, and then select additional software to add to your image.

Let's add Apache's `httpd` as a package under the `Packages` heading. Leave the `Package type` drop-down set to `Individual packages`, enter `httpd` in the search box, and select `httpd` in the list.

.Add the httpd package
image::2026/ib-wiz-packages.png[Add the httpd package]

You will see `httpd` show up in the list of packages below — along with the packages added by the CIS compliance policy we selected — with a version and a retirement date.

.httpd added to the image
image::2026/ib-wiz-pacages-selected.png[httpd added to the image]

[TIP]
====
This retirement date is valuable data. For any supported package you add via this method, you can see at a glance exactly how long you can expect to receive support from Red Hat for that package. In `httpd`'s case, it lives for the entire 10-year lifecycle of RHEL 10, ending in May of 2035.
====

Press `Next`.

== Advanced settings

On the `Advanced settings` page you can configure options such as the filesystem layout, time zone and NTP, users, kernel arguments, and firewall rules.

You will see that our CIS compliance policy has already laid out some custom partitions for us. We could add more by pressing the `+` button at the bottom of the list, but the policy has done a good job of setting a compliant layout, so let's continue on.

.File system configuration defined by the CIS policy
image::2026/ib-wiz-filesystems.png[File system configuration]

Press `Next`.

== Review and build

You will be presented with the review page. Here you can simply save the blueprint by pressing `Create blueprint`, or you can press the down-arrow next to it and select `Create blueprint and build image`. This option can save you some time, so go ahead and click the down-arrow and select `Create blueprint and build image`.

You will be brought to the Images list for your blueprint, and should see your image building.

In the next step of this lab we'll have a look at an image that was built with the same specifications as the one you defined here.
